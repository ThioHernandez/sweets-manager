# بيت الحلوى

نظام لإدارة مشاريع الحلويات المنزلية والعائلية، يساعد على تنظيم الطلبات ومتابعة العملاء والتكاليف والمصاريف والتوصيل من واجهة عربية مناسبة للحاسوب والهاتف.

يعمل البرنامج على جهاز المستخدم، ويحفظ بيانات المشروع في قاعدة SQLite محلية. يمكن استخدامه دون اتصال بالإنترنت؛ مشاركة الرسائل عبر واتساب تتطلب اتصالًا.

## المزايا

- تسجيل طلب يحتوي على عدة أصناف، مع الكميات وموعد التسليم والملاحظات.
- إدارة العملاء والأصناف، مع التعديل والحذف.
- متابعة مراحل تجهيز الطلب وتسليمه، والمدفوع والمتبقي.
- تسجيل مشتريات المواد والكميات والوحدات والأسعار والموردين.
- حساب عدد الوحدات وتكلفة الوحدة عند الشراء بالكرتون.
- تسجيل المصاريف العامة ومتابعة المبيعات والربح.
- إسناد التوصيل إلى موصّل ومتابعة أجره وتسويته.
- إعداد فاتورة نصية أو إيصال مدفوعات أو تحديث حالة لمشاركته عبر واتساب.
- تنزيل نسخة احتياطية واستعادتها.

## التنزيل والتشغيل

اتبع [تعليمات التنزيل والتشغيل](DOWNLOAD-AR.md). بعد التشغيل، راجع [دليل الاستخدام](README-AR.md) لبدء تنظيم مشروعك.

**المتطلبات:** Python 3.10 أو أحدث ومتصفح حديث. لا يلزم Node.js أو npm للاستخدام العادي.

على Windows افتح `Start-Windows.bat`. وعلى macOS أو Linux شغّل من مجلد المشروع:

```sh
python3 server.py
```

ستفتح الواجهة على `http://127.0.0.1:8765`. أبق نافذة البرنامج مفتوحة أثناء الاستخدام.

## طريقة العمل

تُنشأ قاعدة البيانات تلقائيًا عند أول تشغيل في `data/sweets.sqlite3`. ابدأ بإضافة أصناف مشروعك وأسعار البيع وتكاليف الإنتاج، ثم سجّل الطلبات.
البرنامج مخصص للاستخدام على جهاز واحد، ولا يتضمن مزامنة بين الأجهزة أو حسابات مستخدمين. يعتمد الحفاظ على خصوصية البيانات على حماية حساب الجهاز ومجلد البرنامج. لا يوجد تشفير مدمج لقاعدة البيانات.

## للمطورين

الواجهة مبنية باستخدام React وTypeScript وVite. الخدمة المحلية تستخدم مكتبات Python القياسية. تُحفظ مجموعات البيانات بصيغة JSON داخل جدول `app_state` في SQLite.

لإعادة بناء الواجهة، من مجلد `source`:

```sh
npm ci
npm run build
```

انسخ محتويات `source/dist` إلى `web`، مع الاحتفاظ بمجلد `data` عند تحديث برنامج مستخدم فعلي.
ملف `.gitignore` يستبعد قواعد البيانات والنسخ الاحتياطية وملفات البيئة من المستودع. لا ترفع بيانات مشروعك إلى GitHub.
GitHub Pages وحده لا يشغّل خدمة Python وقاعدة SQLite. الاستضافة على خادم وتعدد المستخدمين يحتاجان إعدادًا مستقلًا.

## الخطوط وتبعيات الطرف الثالث

تستخدم الواجهة Janna إذا كان مثبتًا على الجهاز، وإلا خطًا عربيًا بديلًا. ملف Janna التجاري غير مرفق؛ تضمينه ونشره يتطلب ترخيصًا مناسبًا. تبعيات الطرف الثالث تخضع لتراخيص أصحابها.

## تصدير Excel

اضغط «تصدير Excel» أعلى الصفحة لتنزيل جميع السجلات في ملف XLSX، بأوراق عربية منفصلة. التصدير للعرض والتحليل؛ لاستعادة النظام استخدم النسخة الاحتياطية JSON.

## إدارة الموصّلين

من صفحة التوصيل اختر «إضافة موصّل». يتيح زر القلم تعديل الاسم وتحديثه في الطلبات المرتبطة. يمكن حذف الموصّل بعد إزالة ارتباطه بالطلبات؛ يمنع حذف الموصّل المرتبط لحفظ المستحقات. تُحفظ قائمة الموصّلين ضمن النسخة الاحتياطية.

## التقارير

من صفحة «التقارير» اختر الشهر أو فترة من–إلى، ثم نوع التقرير: المبيعات والأرباح، المشتريات، المصاريف، التوصيل، أو التقرير الشامل. حدد الأعمدة المطلوبة بمربعات الاختيار؛ يجب اختيار عمود واحد على الأقل لكل جدول. تتحدث المعاينة والإجماليات تلقائيًا.

يمكن تصفية الطلبات والتوصيل حسب العميل والصنف والموصّل وحالة الطلب والدفع. تُستبعد الطلبات الملغاة افتراضيًا، ويمكن إظهارها باختيار حالتها؛ لا تدخل في ملخص الأرباح والمبيعات. فلتر الصنف يعرض كامل الطلب الذي يحتوي على الصنف. تبقى المشتريات والمصاريف مفلترة بالفترة فقط.

اضغط «تصدير Excel» لتنزيل الأعمدة المختارة مع الفترة والفلاتر والإجماليات، أو «طباعة / حفظ PDF» ثم اختر حفظ بصيغة PDF في نافذة المتصفح. يفضل تقليل عدد الأعمدة عند الطباعة لسهولة القراءة. أدخل اسمًا ثم اضغط «حفظ الإعداد» لإعادة استخدام الخيارات لاحقًا؛ يُحفظ الإعداد محليًا ويشمله النسخ الاحتياطي.

تاريخ الطلب هو موعد الطلب المسجل، وليس تاريخ إنشاء الفاتورة أو التحصيل. المدفوع هو القيمة المسجلة حاليًا على طلبات الفترة؛ لا يمثل تحصيلًا نقديًا خلال الفترة لعدم تسجيل تاريخ كل دفعة. صافي الربح تقديري: ربح الطلبات غير الملغاة ناقص مصاريف الفترة. لا تخصم المشتريات مرة أخرى عندما تكون تكلفة المواد محسوبة ضمن تكلفة الأصناف. عند استخدام فلاتر الطلبات تبقى مصاريف الفترة كاملة؛ لذلك لا يعتبر الصافي ربحًا خاصًا بعميل أو صنف.
